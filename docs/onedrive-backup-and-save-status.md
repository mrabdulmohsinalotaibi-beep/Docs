# ربط OneDrive والتمييز بين الحفظ المحلي والنسخ السحابي

## الهدف
الجهاز هو المصدر الأول للمستندات الجديدة. يُحفظ كل تعديل محليًا مع التحقق من نجاح الكتابة ثم إعادة القراءة، وتُنسخ البيانات إلى OneDrive الخاص بالمستخدم تلقائيًا عند توفر اتصال وتفويض صالح. لا تنفذ عملية رفع لمجرد ظهور اتصال الشبكة إذا كان التطبيق مغلقًا أو قيّده النظام.

## تجربة المستخدم
- الإعدادات > النسخ الاحتياطي > «ربط حساب OneDrive» عبر Microsoft OAuth 2.0 Authorization Code + PKCE وموافقة صريحة.
- يوضح الموقع أن الربط لكل حساب مستقل، ولا يطلب كلمة مرور Microsoft، ولا يتيح لمدير الموقع قراءة النسخ.
- في الشريط أعلى جميع الصفحات ثلاث حالات مستقلة (المرجع الحالي: docsLocalIndicator وdocsPeerIndicator في src/page.html):
  1. الحفظ بالجهاز: أصفر «جارٍ الحفظ»؛ أخضر «تم الحفظ محليًا» بعد اكتمال معاملة IndexedDB والتحقق بإعادة القراءة؛ أحمر «تعذر الحفظ».
  2. نسخة OneDrive: رمادي «غير مربوط»؛ أصفر «بانتظار الإنترنت/جارٍ الرفع»؛ أخضر «نسخة مشفرة محدثة حتى [وقت]» بعد استجابة Graph upload وتثبيت manifest والتحقق من اكتمال النسخة؛ أحمر «فشل النسخ».
  3. مزامنة الأجهزة: الحالة الموجودة حاليًا، لا تخلط مع نجاح النسخ السحابي.
- «تم الحفظ» تخص الجهاز فقط ولا تُعرض بوصفها نجاح النسخ إلى OneDrive.
- يوضح آخر رفع ناجح، الحجم وعدد المستندات والمرفقات المشمولة، وآخر فشل، ويعرض زر «النسخ الآن» و«استعادة» و«إلغاء الربط».
- عند عودة اتصال الإنترنت أو فتح التطبيق مع جلسة فعالة، يستأنف طابور النسخ تلقائيًا. لا ضمان للعمل في خلفية iOS PWA المغلق.

## أمان وسلامة البيانات
- استخدم MS Graph app folder (Files.ReadWrite.AppFolder عند دعم الحالة المطلوبة) مع OAuth PKCE؛ خزّن الرموز بتصميم يحد من تسربها ولا تحفظ access/refresh tokens بالنص الصريح في localStorage. تحقق من سياسات Graph وMicrosoft Entra قبل التنفيذ.
- لا ترفع أي ملف بيانات طالب إلا بعد تشفيره محليًا AES-256-GCM بواسطة مفتاح يولّد من عبارة استعادة مستقلة، مع salt وKDF مُعدّين بشكل آمن. لا ترسل العبارة أو مفتاح فك التشفير إلى الخادم أو OneDrive. وضّح للمستخدم أن فقد العبارة يعني تعذر فك النسخة.
- قيّد جميع النسخ بمعرف حساب Docs وبصمة manifest ونسخة schema ومعرف الجهاز وتاريخ الإنشاء؛ تحقّق من سلامة كل جزء بعد تنزيله.
- دعم حزم كبيرة ومرفقات عبر upload sessions واستئناف الرفع، دون كشف نصوص مستندات الطلاب داخل سجلات الأخطاء.
- لا تحذف أي نسخة سليمة قبل التحقق من الجديدة. احتفظ بنسخ مؤرخة 60 يومًا، مع سياسة تمنع خلو الأرشيف إن توقف النسخ فترة طويلة؛ لا تنفذ مسحًا من OneDrive إلا بعد موافقة المستخدم على السياسة.
- استعادة معاينة أولًا، ثم دمج دون الكتابة على أحدث تعديل؛ التعارض يحتفظ بالنسختين.
- التأكد من أن النسخة تشمل IndexedDB والمرفقات والإعدادات المحلية بالإضافة إلى بيانات الحساب المنقولة التي تم جلبها بالكامل؛ إذا كان الجرد ناقصًا، تُعرض عبارة «نسخة جزئية» ولا «مكتملة».

## دورة الحالة
unlinked -> waiting-auth -> idle -> local-changed -> pending-network -> encrypting -> uploading -> verifying -> synced
مع مسار failure لكل مرحلة، وإعادة محاولات exponential backoff مع jitter، واحترام 429/Retry-After.
تحتفظ قاعدة IndexedDB بسجل outbox مستقل لكل حساب: revision, pendingAt, attempt, lastSuccess, manifestHash.
لا تساوي event online نجاح اتصال Graph. لا ترفع البيانات مجددًا إن لم يتغير digest مقارنة بأحدث نسخة مؤكدة.

## اختبارات قبول إلزامية
1. الحفظ ثم فصل الإنترنت، إعادة التحميل، فتح المستند؛ نجاح الحفظ المحلي دون اتصال.
2. تعديل بدون شبكة: يظل المؤشر المحلي أخضر والسحابي أصفر؛ عند الاتصال وفتح التطبيق يُرفع أحدث إصدار ويصبح السحابي أخضر بعد التحقق.
3. إغلاق التطبيق أثناء الرفع؛ استئناف صحيح دون حذف النسخة السابقة.
4. رفض Microsoft OAuth أو إلغاء الربط؛ لا مساس بالسجلات المحلية.
5. تعارض بين جهازين؛ لا حذف ولا استبدال صامت.
6. ملف صورة كبير وفهرس غير مكتمل؛ عدم إظهار «نسخة مكتملة» كذبًا.
7. اختبار استعادة شامل على قاعدة مؤقتة مع مطابقة hashes والعدادات وتوقيعات وصور.
8. عزل حسابين على الجهاز نفسه، ومنع الوصول إلى بيانات الآخر.
9. iPhone Safari/PWA وAndroid Chrome، وحالات نفاد التخزين ورفض quota.

## حالة التنفيذ
هذه مواصفات تنفيذية، وليست ميزة مفعلة. لا تضع شارة خضراء للنسخ السحابي قبل اكتمال الربط والاختبارات والنشر الفعلي.
